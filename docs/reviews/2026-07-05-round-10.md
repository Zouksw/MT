# Round 10 — 前端测试修复（is-core-module 损坏）

**Date:** 2026-07-05
**Status:** ✅ Complete
**Track:** 持续项（前端测试基础设施）
**Priority:** P1

## 背景

Round 9 发现前端 Jest 配置"损坏"（`npx jest` 报 `Module <rootDir>/jest.setup.js in setupFilesAfterEnv not found`），当时归因为 Next.js 15 `next/jest` API 变化，记为待修。

## 根因（与 Round 9 初判不同）

**不是 `next/jest` 配置问题** —— 配置一直是对的（`rootDir` / `<rootDir>` 宏解析均正常，`next/jest` resolver 返回正确对象）。

**真正根因：`is-core-module@2.16.1` 的 `core.json` 文件物理丢失。**

调试链：
1. Jest 配置读取阶段对 `setupFilesAfterEnv` 做存在性校验 → 调 `findNodeModule`
2. `findNodeModule` → `defaultResolver` → `resolve.sync` → 内部 `require('is-core-module')` 判断是否 Node 内建模块
3. `is-core-module/index.js:65` 执行 `require('./core.json')` → **文件丢失 → throw**
4. `findNodeModule` 捕获异常返回 `null`（不抛出）→ Jest 报误导性 "setup file not found"

这是**第三次磁盘损坏**（与 Round 5 js-yaml、Round 7 inference venv 同源）：
- Round 5：`js-yaml/lib/...` 文件丢失
- Round 7：inference venv `click.core` / `idna.core` 丢失
- Round 10：`is-core-module/core.json` 丢失

疑似 `pnpm prune` / 磁盘清理误删包内非 `.js` 数据文件（`core.json` 是 5.9KB 的内建模块清单）。

## 修复

```bash
pnpm store prune                                    # 清理失效引用（删 5750 文件 / 215 包）
rm -rf node_modules/.pnpm/is-core-module@*          # 删损坏副本
pnpm remove is-core-module
pnpm add -D is-core-module@2.16.1 --force           # 强制重下（不复用损坏缓存）
```

验证 `core.json` 恢复（5953 字节）。

## 反复损坏模式（需根治）

三次损坏均指向同一根因 —— 包管理器 store 的文件被外部清理误删：

| 轮次 | 受害文件 | 影响 |
|---|---|---|
| Round 5 | `js-yaml/lib/*.js` | backend dev 工具链 |
| Round 7 | inference venv `.py`（click.core/idna.core）| **AI 服务完全瘫痪** |
| Round 10 | `is-core-module/core.json` | 前端测试无法运行 |

**建议（后续运维）：**
1. 排查是否存在 cron / 系统清理任务触碰 `/root/.pnpm-store`、`/root/inference-service/venv`、`/root/frontend/node_modules/.pnpm`
2. 考虑把这些路径加入清理白名单，或改用只读 bind-mount 保护
3. 增加 `is-core-module/core.json` 存在性的启动健康检查（类似 inference `/health`）
