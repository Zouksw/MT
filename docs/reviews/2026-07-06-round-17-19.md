## Round 18 — P0-1 predictionCache 静默吞错

### 症状
`prediction_logs` 在 03:48 后 8 小时无新增行，但调度日志仍打 `Refreshing predictions`、Redis 缓存仍更新（130 个 key）。**调度在跑、缓存更新、日志没落库。**

### 根因
`backend/src/services/predictionCache.ts:137` 和 `:141` 两处 `.catch(() => {})` 把 `logPrediction()`（Prisma 写 prediction_logs）的失败**静默吞掉**。这与 ROADMAP 第 12 轮自述的"worker 静默吞异常"是**同类 bug 在另一条路径复发**——第 12 轮修了 predictionQueue worker，但 predictionCache（并行预测路径）的同款吞错仍在。

### 修复
两处空 catch → `logger.error`，带上下文（modelId/commodityId/MAPE 阶段）。**保持非阻塞**——预测仍返回成功（caller 依赖），只有 MAPE log 丢失，但现在可观测。

### 回归测试（gen-tests 铁律）
新增 `backend/src/services/__tests__/predictionCache.runAndCache.test.ts`（3 测试，`vi.hoisted` 模式）：
- **"logs an error when logPrediction fails"** —— **回退修复后 FAIL**（`logger.error` called 0 times，正是静默吞错），**应用修复后 PASS** ✅
- "returns cached prediction even when logPrediction fails" —— 钉住非阻塞契约
- "caches and logs a successful prediction" —— happy path

## Round 18 — P0-2 数据采集停摆根因（定位，非代码修复）

### 症状
MAPE 验证环断裂：747 条合格（≥7 天）completed 预测里 **691 条 actuals_after=0**（预测时刻之后无新 daily 价格）。

### 根因（逐层取证）

**层 1** — 18 源里仅 3 个真产数据：cme_futures（246K updated，但 source='cme'/'fred' 落表）/ commodity_prices（186，仅 3 外汇）/ world_bank（264）。其余 16 源 success 但 inserted=0/updated=0。

**层 2** — "246K updated" 是**虚胖计数**：`helpers.ts:100` `upsertPrice` 行已存在一律返回 `updated:1`，**不比值**。FRED 每次重抓 7 天 → 重 upsert 相同 3 行 → 累积 246K"updated"。实际新数据 = 0。

**层 3（真根因）** — FRED 系列**自身滞后/停发**：
```
curl 'https://fred.stlouisfed.org/graph/fredgraph.csv?id=DCOILWTICO&cosd=2026-06-25&coed=2026-07-06'
→ 最新行只到 2026-06-29，7/1-7/6 无数据
```
FRED 的 DCOILWTICO / DHHNGSP 上游未发新数据。**非代码 bug。**

**层 4** — Stooq 备用路径被 Cloudflare 拦（代码注释 `cmeFutures.ts:270` 写"may be Cloudflare-blocked"）：Gold/Wheat/Corn/Coffee 等仅 1-2 行停在 5/17-19。

### 结论
**P0-2 不是单点代码修复，属 ROADMAP 主线 A（数据覆盖）第 13 轮的具体阻塞确认。** 精确阻塞点：① FRED 系列 lag；② Stooq 被拦；③ 16 源解析失效；④ upsertPrice 计数虚胖（次要）。**归入主线 A 排期，本轮不单独修。**

## Round 19 — P1-8 加索引（修正初版误报）

### 初版误报纠正
初版（+ Explore agent）称"5 个外键缺索引"。**review skill 逐条回查 schema 后修正：只有 1 个真缺。**

| Model | FK | 实际覆盖 | 真缺？ |
|---|---|---|---|
| Dataset | organization_id | `@@unique([organization_id, slug])` 左前缀 | ✗ |
| Timeseries | datasetId | `@@unique([datasetId, slug])` 左前缀 | ✗ |
| organization_members | organization_id | `@@unique([organization_id, user_id])` 左前缀 | ✗ |
| **WatchlistItem** | **commodityId** | unique 复合的**右列**，btree 不覆盖 | **✓** |
| Subscription | userId | `@@unique([userId])` 单列全索引 | ✗ |

> Postgres btree 复合索引覆盖左前缀，不覆盖右列。

### 修复
```prisma
model WatchlistItem {
  ...
  @@unique([watchlistId, commodityId])
  @@index([watchlistId])
  @@index([commodityId])   // ← 新增
  @@map("watchlist_items")
}
```
