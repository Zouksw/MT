## A 线:失效源诚实标记 + 诊断

### 诊断结论(实测)
A1 审计指出的 8 个"无 key 却零产出"源,经实测**外部端点全部失效**:
- dceFutures/czce: dce.com.cn/czce.com.cn 旧 JSON 端点 404
- faoPrices: fenixservices.fao.org 超时(15s 不可达)
- usdaPsd: apps.fas.usda.gov PSD API 404(路径迁移)
- balticDry: FRED `BALTIC_DRY` series 404 + 主源 Baltic Exchange 不可达

逐源重写需深度调研每个替代端点(多数已迁移或需认证),成本高、易引入脆弱抓取代码。按 CLAUDE.md"最小代码、不投机",本轮**不做暴力重写**,改为诚实标记。

### 实施:消除"success+0 掩盖"
- `scraperManager.runSource`:缺 key 跳过时,logger.debug → **logger.warn**,返回 `{skipped:true, skipReason}`(原来返回 `{inserted:0,updated:0}` 被当 success)
- `server.ts` runSourcesAndLog:skipped 记 `status="error"` + errorMessage(原来记 success/warning)
- **效果**:数据新鲜度看板如实反映"6 个源因缺 key 停摆",不再显示假的 healthy

### A3 缺口商品现状
72 个无价格商品,beef_cuts 占 29 个(40%)。根因多是源坏了——不修源补不了。本轮诚实标记让问题可见,留待 key 到位 + 端点替代方案确定后专项修复。

## B3:AI 功能分层(修 M7)

### 背景
M7:aiAccess 中间件只查 `req.user` 存在,VIEWER(免费)可无限制调 AI。且 aiAccess 是**死代码**(无路由引用)。CLAUDE.md 定位 AI 是计费层功能。

### 实施
- **aiAccess.ts** 加 Layer 3 套餐门控:VIEWER(免费)→ 403 "Pro subscription required";EDITOR/ADMIN(Pro+)放行。复用现有 UserRole 体系,无需查 Subscription(避免每次 AI 调用查 DB)
- **inference.ts** 6 个 AI 端点(predict/batch/visualize、anomalies/visualize、models/train)的 `authenticate` → `checkAIAccess`;只读端点(status/models 列表/详情)保持 authenticate(免费层可看有哪些模型)
- **测试同步**:旧测试断言"VIEWER 允许"改为"VIEWER 拒绝(M7 修复)";MODERATOR(测试编造,非 enum)改 EDITOR

### 价值
AI 端点从"任何登录用户无限调"变为"Pro 层专属",符合"信息平台 + AI 功能分层"定位。为未来真实计费(Stripe 接入)预留门控点。
