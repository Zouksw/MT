## 完成项

### C3. Next.js 15.5.15 → 15.5.20（安全 patch 升级）

ROADMAP 原定 15.5.18，但 15.5.20 是最新 patch 且覆盖更多 advisory，故升级到 15.5.20。

**结果：8 个 Next.js high 漏洞全部清零**（pnpm audit 中 `Next.js` 相关 high/critical 条目从 8 → 0）：
- Middleware / Proxy bypass (App Router + Pages Router)
- SSRF in Server Components
- DoS via connection / Server Components
- XSS in App Router / beforeInteractive
- Cache poisoning in RSC

**附带清理（休眠 bug 唤醒）：**
- `next.config.mjs` 仍包裹 `withNextIntl(...)` 并 import 已删除的 `next-intl/plugin`（Round 5 删 i18n 时遗留）。生产用缓存 build 掩盖了此问题，新装依赖后 build 直接失败。
- 移除 `createNextIntlPlugin` import + `withNextIntl` 包装，config 现在直接 `export default withBundleAnalyzer(...)(nextConfig)`。
- 同时清理了 `next-intl` 这个孤儿依赖（pnpm 自动移除）。

**验证：** frontend `pnpm build` 成功（所有路由编译通过），`/login` 200，`/api/auth/me` 经 proxy 返回 401（正确）。

### C2续. metrics.ts 抽 service（最后一个胖路由）

`routes/metrics.ts` **657 → 388 行**，业务逻辑下沉到新建 `services/metricsService.ts`（~330 行）。

**service 拥有：**
- 进程级单例状态：`endpointMetrics` Map + `totalRequestCount`（模块级变量，Node 单例语义）
- `recordRequest(endpoint, durationMs)` — 路由的 `res.on("finish")` hook 调用
- 格式化：`formatUptime` / `formatBytes`
- 统计：`percentile` / `getEndpointSnapshot` / `getResponseTimeDistribution` / `getGlobalDurationsSorted` / `getTotalRequestCount`
- Web Vitals Redis 层：`storeWebVital` / `getWebVitalsSummary` / `getWebVitalsHistory` / `getSummaryWebVitals` / `getActiveUserCount`
- 常量：`VALID_WEB_VITAL_NAMES` / `PERIOD_SECONDS` / `INTERVAL_SECONDS`

**路由保留：**
- HTTP 边界：auth、validation、response shaping
- `res.on("finish")` 计时 hook（需要 raw req/res，无法下沉）
- 6 个 endpoint handler（全部瘦身为调用 service + `success(res, ...)`）

### 附带修复：web-vitals 摄入回归（休眠 bug）

重构时发现：`POST /web-vitals` 路由层有 `authenticate`，但 `router.use` 的 "POST /web-vitals 跳过认证" 例外被它压过，且前端 `WebVitals.tsx` **不带 Authorization 头**发送——结果每次用户访问都尝试上报 vitals，全部 401 静默失败。

**修复：** 路由层移除 `authenticate`，恢复 `router.use` 的 public-ingestion 契约。

**验证：** 无 auth POST `/web-vitals` → 200 `stored:true`；GET `/web-vitals?period=24h` 读回 LCP count:1 avg:2.5（round-trip 成功）。
