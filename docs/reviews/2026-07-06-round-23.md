## A. ✅ 错误消息 shape bug（前端 3 文件）

### 根因（live 取证）
后端 `errorHandler.ts` 对所有错误返回统一 shape：
```json
{"success": false, "error": {"message": "Missing required parameter: commodityId", "code": "BAD_REQUEST"}}
```
但 3 个前端 caller 读 `error.error`（即整个 error 对象）：
- `ai/predict/page.tsx:143-146`：`new Error(error.error || "Prediction failed")`
- `ai/anomalies/page.tsx:110`：`new Error(error.error || "Detection failed")`
- `forecasts/create/page.tsx:152`：`new Error(errData.error || "Failed to generate forecast")`

`error.error` 是 `{message, code}` 对象（truthy）→ `new Error({...})` → toast 显示 **`[object Object]`**，真实错误信息被吞。

### 修复（3 处统一）
`error.error` → `error.error?.message`（提取嵌套 message，保留 fallback）。forecasts 用 `errData.error?.message`。

### live 验证
触发 `POST /api/inference/predict {}`（缺 commodityId）→ backend 返回 `error.message: "Missing required parameter: commodityId"`。前端现在能正确提取此消息（原会显示 `[object Object]`）。

## B. ✅ upsertPrice 计数虚高（ingestion 指标失真）

### 根因（Round 18 已定位，本轮修）
`dataIngestion/helpers.ts:upsertPrice` 用 `findUnique({select:{id}})` 查存在性，**不比值**——行存在一律返回 `{updated:1}`。FRED 路径每次重抓最近 7 天 → 重 upsert 相同 3 行 → 累积 **246K "updated"**（实测），实际新数据 = 0。这让 `ingestion_logs` 的 updated 列完全失真，运营无法判断哪些源真在产新数据。

### 修复（surgical）
- `findUnique` 改 `select: {id, open, high, low, close, volume}`（多取值用于比对）
- 行存在且 OHLCV 全相等 → 提前 return `{inserted:0, updated:0}`（no-op，不入两指标）
- 行存在但值变 → 继续 upsert，返回 `{updated:1}`（原行为）
- 行不存在 → 创建，返回 `{inserted:1}`（原行为）

**向后兼容：** `ScraperResult` 类型仍 `{inserted, updated}`；调用方 `inserted += r.inserted; updated += r.updated`——no-op 返回的 0/0 不入任何指标，正确。

### 回归测试（gen-tests 双向验证）
新增 `__tests__/upsertPrice.test.ts`（5 测试，真实 Postgres）：
- 首次写 → `{inserted:1, updated:0}` ✓
- **重写相同值 → `{inserted:0, updated:0}`**（**回退修复 FAIL，应用 PASS** ✓）
- 改 close → `{updated:1}` ✓
- 改 volume → `{updated:1}` ✓
- null volume 双侧 → 相等（无 update）✓（**回退修复 FAIL，应用 PASS** ✓）
