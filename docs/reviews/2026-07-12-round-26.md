# Round 26 — Inference slug/UUID resolution (pre-existing bug fix)

**Date:** 2026-07-12
**Skill:** `investigate` (5-phase) + `gen-tests` (bidirectional Iron Law)
**Type:** Pre-existing bug fix — root cause found in prior rounds, fixed here.
**Scope:** `backend/src/routes/inference.ts` (+ regression test)

## Problem

`POST /api/inference/predict` (and `/predict/visualize`, `/anomalies`,
`/anomalies/visualize`, `/predict/batch`) failed with `500 SERVER_ERROR` whenever a
caller passed a commodity **slug** instead of a UUID.

```
slug  crude_oil_cme → 500 "Insufficient price data for commodity crude_oil_cme: 0 points"
UUID  6c48ded5-...  → 200 { values: [5] }
```

The frontend AI Predict page sends a slug (`formTimeseries`, default
`"root.test2"`, user-entered), so the feature was broken end-to-end for any real
commodity.

## Root cause (Phase 3)

The route forwarded the caller's `commodityId` body field straight to:

- `predictFromCache({ commodityId })` →
  `getCommodityPriceValues(commodityId)` →
  `prisma.commodityPrice.findMany({ where: { commodityId } })`

`CommodityPrice.commodityId` is a UUID FK. A slug like `crude_oil_cme` matches
**zero** rows → `< 2 points` guard throws → 500.

The sibling route `routes/signals.ts:258-270` already solved this with an
`isUuid` regex + slug fallback query. The inference routes never adopted the
same pattern.

**Evidence:** `crude_oil_cme` resolves to UUID `6c48ded5-3b13-4d39-95e0-680d4e89c153`,
which has **10,197** daily price points. The slug matched 0.

## Fix (Phase 4 — minimal)

Added one helper at the top of `routes/inference.ts`, mirroring `signals.ts`:

```ts
const UUID_RE = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

async function resolveCommodityId(input: string): Promise<string> {
  if (UUID_RE.test(input)) return input;            // already a UUID
  const commodity = await prisma.commodity.findFirst({ where: { slug: input } });
  if (!commodity) {
    throw new BadRequestError(`Commodity "${input}" not found. ...`);  // 400, not 500
  }
  return commodity.id;
}
```

Each of the 5 routes now calls `const uuid = await resolveCommodityId(commodityId)`
once after the missing-field check, then uses `uuid` for:

1. the cache key (`cacheKeys.prediction(uuid, ...)`) — so the route now **shares
   the background-prewarmed cache** that `predictionCache.ts:250` fills keyed by
   UUID; previously slug requests never hit cache,
2. `predictFromCache({ commodityId: uuid })`,
3. every `prisma.commodityPrice.findMany({ where: { commodityId: uuid } })`.

The caller's original input slug is echoed back unchanged in the `commodityId`
response field (display concern only).

`/predict/batch` resolves inside the existing per-row `try` so an unknown id is
reported in that row's result (preserving the batch's per-row error contract)
rather than failing the whole batch.

### Security note

Unknown ids return `400 BAD_REQUEST` with the same message regardless of whether
the id was a UUID or a slug — no existence enumeration leak. The message matches
`signals.ts:268` verbatim for consistency.

## Regression test (Phase 5 — bidirectional)

New file: `backend/src/routes/__tests__/inference.test.ts` — 5 integration tests
via supertest against the real DB:

1. `accepts a commodity SLUG and returns a prediction (regression)` — the core
   case; asserts 200 + values + echoed slug.
2. `still accepts a raw UUID` — no regression for UUID callers.
3. `returns 400 for an unknown commodity slug` — asserts 400 (not a 500 leak).
4. `accepts a slug in /predict/visualize` — the endpoint the frontend AI page
   actually calls; asserts historical rows + prediction.
5. `accepts a slug in /anomalies` — asserts statistics shape.

**Bidirectional verification (gen-tests Iron Law):**
- Temporarily mutated `/predict` to `const uuid = commodityId` (bypass
  resolution).
- Tests 1 + 3 **FAILED** (slug → 500 again; unknown slug → 500 not 400).
- Restored the fix → all 5 **PASS**.

A test that can't be made to fail is not a test — these can.

## Bonus: cache alignment

Because the route now keys the cache by UUID, a slug request hits the same
prewarmed entry that `predictionCache.ts` (the 30-min scheduler) fills. The live
test showed `cached: true` on the **first** slug request — previously slug
requests could never hit cache and always ran a fresh (slow) inference call.
