## 背景

2026-07-05 exploration 发现 inference service (port 10810) **完全宕机**：

- 根因：venv 损坏 — `click.core` / `pip._vendor.idna.core` 等 `.py` 文件物理丢失（与之前 pnpm store js-yaml 损坏同源，疑似磁盘清理 / 包管理器 prune 误删）
- pip 自身损坏，无法自修复
- 结果：所有 AI 端点（predict / batch / visualize / anomalies / visualize / models/train）的 backend→inference 调用全部超时失败，110 商品 × 30min 的预测调度全部静默失败

## 完成项

### 1. 重建 inference venv

```bash
cd /root/inference-service
rm -rf venv
python3 -m venv venv
./venv/bin/python -m pip install --upgrade pip
./venv/bin/python -m pip install -r requirements.txt
```

**重装包（关键）：** fastapi 0.139, uvicorn 0.50, torch 2.12, chronos-forecasting 2.3.1, sktime 1.0.1, statsmodels 0.14.6, scikit-learn 1.7.2, transformers 5.13, accelerate 1.14

**验证：** `import click / fastapi / chronos / torch / sktime` 全部通过；`from main import app` 加载成功。

### 2. 纳入 PM2 自动管理

`ecosystem.config.cjs` 新增 `mt-inference` app：

- script: `inference-service/venv/bin/python`
- args: `-m uvicorn main:app --host 0.0.0.0 --port 10810`
- cwd: `inference-service`
- max_memory_restart: `2G`（torch + chronos 内存占用大）
- kill_timeout: `10000`（torch 模型卸载慢）
- listen_timeout: `30000`（冷启动 ~10s）
- min_uptime: `15s`，restart_delay: `5000`
- env: `INFERENCE_HOST/PORT/LOG_LEVEL`

`pm2 save` 已持久化进程列表。

### 3. 修复 checkAIAccess 缺失 authenticate 的回归（重大发现）

Tier-gating 重构（之前 B3 改造）时引入的严重回归：`routes/inference.ts` 6 个 AI 端点把 `authenticate` 直接替换成了 `checkAIAccess`，导致 `req.user` 永远为空，**Layer 2 永远抛 403**。

**表现：** 即便 ADMIN 也无法调用任何 AI 端点 — "Authentication required for AI features."

**修复：** `inference.ts` 6 处路由全部改为 `authenticate, checkAIAccess,` 链式调用：

- `/predict`
- `/predict/batch`
- `/predict/visualize`
- `/anomalies`
- `/anomalies/visualize`
- `/models/train`

（注：`models.ts` 的 `/train` 与 `/:modelId/predict` 此前已是正确的 `authenticate → checkAIAccess` 链，未受影响；`/status` 故意保持无认证以便健康探针。）
