## 完成项

### 1. tradingSignals — STL 发散修复（质量问题）

**问题**：STL forecaster 对真实长序列（crude_oil 200 点）预测 99.62（实际 71.87），甚至负值 -240。根因：`np.polyfit` 对全序列 STL 趋势分量做线性外推，但真实商品价格有长期趋势（如原油多年下跌），线性外推必然发散。

**修复**：改为 damped-drift 预测 —— 锚定最后观测值，用最后一个周期（period）的趋势分量取平均斜率，sqrt 阻尼后做多步外推：
```python
pred = last_val + sign(local_slope) * sqrt(abs(local_slope)) * steps
```
**效果**：crude_oil STL 从 99.62 → **65.46**（合理：锚定 71.87 + 轻微下行斜率）。5 模型预测全部落在合理区间，共识信号置信度从虚高 1.0 调整为 0.82（STL 的下行预测拉低了共识）。

### 2. backtest — 自动验证任务（MAPE 闭环缺失）

**问题**：backtest 的 `runBacktest` 只读 `status='verified'` 的 prediction_logs 来算 MAPE，但 `verifyPrediction(logId, actuals)` 从未被自动调用 —— 那 24 条 verified 全是测试数据（test-model-*），真实模型 0 verified。导致 backtest 永远 `mape: null, trend: insufficient_data`。

**修复**：新建 `verifyDuePredictions()` —— 扫描 `status='completed'` 且预测已过 7 天的 prediction_logs，取该商品预测窗口内的实际日收盘价，调 `verifyPrediction` 计算 MAPE 并标 verified。闭环：`completed → verified`。

**接入**：`server.ts` 每日调度 `verifyDuePredictions()`。

**现状说明**：当前 verified=0 是因为本会话的 completed 预测都不到 7 天（未到验证窗口）。下次调度运行 + 数据积累后，backtest 会逐步有真实 MAPE。代码路径已打通并验证逻辑正确。
