### live 验证（用 UUID 绕过预存在 slug bug）
```
POST /api/inference/predict {commodityId: <UUID>, ...}
→ {success: true, data: {timestamps, values[10], lowerBound, upperBound, algorithm, cachedAt, commodityId, horizon, cached: true}}
```
信封正确生效。

### ⚠️ 发现预存在 bug（非本轮引入，不修）
`/api/inference/predict` 传 slug（`crude_oil_cme`）但 `getCommodityPriceValues` 查 `where: {commodityId}` 期望 UUID → 抛 "Insufficient price data: 0 points"。**这是另一会话改 inference flow 时遗留的 slug/UUID 不匹配**，不是我的信封改动（信封在错误抛出之后才执行）。用 UUID 调用则信封正常。**建议下一轮修：路由层加 slug→UUID 解析（同 signals.ts:258-265 的 isUuid 判断模式）。**
